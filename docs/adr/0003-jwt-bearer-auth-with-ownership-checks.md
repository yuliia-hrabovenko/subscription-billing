# Customer authentication via self-issued JWT bearer tokens, authorized by per-request ownership checks

We authenticate customer-facing API requests with bearer JWTs, validated by Spring Security's OAuth2 Resource Server support, issued by this service itself rather than a third-party identity provider (e.g. AWS Cognito, Auth0) or session cookies. Authorization is a single `CUSTOMER` role — there is still no admin role in v1, consistent with the existing "no admin override" decision (`product-design.md` §3) — plus a mandatory service-layer ownership check on every request: the authenticated customer's ID must match the `customerId` on the target Subscription/Invoice, independent of and in addition to the role check.

We considered a managed IdP instead of self-issued tokens, but rejected it for v1. `CLAUDE.md` requires a documented reason before adding a managed AWS service, and a single-role, no-admin, US-only system doesn't need federation, social login, or centralized MFA policy — the features a managed IdP earns its keep on. Self-issued JWTs keep auth inside the same modular monolith as everything else, with no new external dependency. Revisit if a future requirement (SSO, enterprise buyers, an admin console with its own RBAC) makes a managed IdP's feature set worth the added dependency and operational surface.

Role membership alone is not sufficient authorization, because there is only one role: a `CUSTOMER` token is valid proof of *a* customer, not proof of *which* customer, so every handler must still check resource ownership before acting. A request for another customer's Subscription or Invoice fails with `403`, not a `404` (which would leak existence) or a silent success. Two endpoints are explicit exceptions to the bearer-token requirement: `POST /api/v1/subscriptions` (signup) must be reachable pre-token, since it's how a customer's identity and first token are established; `POST /api/v1/webhooks/gateway` is never customer-authenticated — it authenticates the *gateway*, via signature verification, an entirely separate mechanism from customer JWTs.
